# 테이블 레퍼런스 — customers · support_tickets · usage_monthly

다음에 이 테이블을 쓰는 Claude가 먼저 읽는 문서. 숫자는 모두 SQL로 센 값이다(2026-11-19 프로파일링, 읽기 전용 쿼리).

## customers

- **그레인**: 고객 1명. 50,000행 × 13컬럼.
- **키**: `customer_id` (50,000 고유, null 0, C000001~C050000).
- **기간**: 가입일 `signup_date` 2018-12-25 ~ 2025-12-31 / 이탈일 `churn_date` 2025-01-01 ~ 2025-12-31.
- **조인**: 기준 테이블. support_tickets·usage_monthly가 `customer_id`로 N:1 연결된다.
- **월별 가입**: 대체로 550~660건. 2018-12는 133건(부분월), **2024-12는 25건**(2024-12-03~31 가입 0건), 2025-01 345건, 2025-02 401건. 완전히 빠진 달은 없다.
- **값**: 이탈 7,256명(14.5%) / 비이탈 42,744명. 플랜은 5종, 플랜마다 `monthly_fee`가 하나뿐(알뜰 19,000 · LTE기본 33,000 · LTE무제한 45,000 · 5G스탠다드 55,000 · 5G프리미엄 89,000).
- **쓰면 안 되는 컬럼**
  - `customer_name`: 고유 22,742개, 최대 9명 동명이인 → 식별자가 아니다.
  - `visitor_id`, `campaign_id`: 43,515행(87%)이 null. 값이 있는 6,485행은 2025-01-01 이후 가입자와 건수가 같다. 전체 고객 기준 분석에 쓰면 편향된다.
  - `monthly_fee`: `plan_type`과 1:1이라 별도 정보가 없다.
  - `churn_date`·`is_churned`: 이탈일이 2025년에만 있다. 전체 기간 이탈률로는 부적절하고 2025년 이탈로 한정해야 한다.
- **데이터를 만든 사람에게 물을 것**
  1. 2024-12-03~31 가입 0건, 2025-01~02 저조(345/401건)는 장애·이관 누락인가, 실제인가?
  2. `visitor_id`·`campaign_id`가 2025년 이후 가입자에게만 있는 이유는?
  3. 캠페인 귀속 6,485건 중 5,590건(86%)이 `signup_date`가 캠페인 start~end 밖이다. 어떤 기준으로 붙였나?
  4. 오프라인 채널 4,037건 중 `campaign_id`가 있는 557건은 무엇인가?
  5. 2024년 이전 이탈 고객은 삭제됐나, 처음부터 안 담았나? `is_churned`는 어느 시점 기준인가? (가입 2025 이전 43,515명 중 이탈 6,726명 15.5% / 2025 가입 6,485명 중 530명 8.2%)
  6. 동명이인은 중복·재가입이 아닌가?
  7. 과거 요금 개편·할인·결합은 `monthly_fee`에 반영되지 않았나?

## support_tickets

- **그레인**: 문의 1건. 32,789행 × 10컬럼.
- **키**: `ticket_id` (32,789 고유). `customer_id`(23,398 고유)와 `agent_id`(120 고유 = agents 120행, 고아 0)는 외래키.
- **기간**: `created_date` 2025-01-01 ~ 2025-12-31. 빠진 달 없음, 월별 2,539(2월) ~ 2,883(12월).
- **결측**: 10개 컬럼 모두 null 0.
- **조인**: customers와 **N:1**. customers에 없는 `customer_id` 0개. customers에 LEFT JOIN 하면 **32,789행**(그대로). customers 기준으로 보면 문의 없는 고객이 26,602명(50,000 − 23,398). 문의일이 가입일보다 앞선 건 0, 해지일 이후 문의 0.
- **값**: 채널 전화 14,324 · 챗봇 7,967 · 앱 6,865 · 이메일 3,633 / 상태 완료 29,772 · 진행중 2,002 · 보류 1,015 / `is_recontact` true 7,427 · false 25,362 / `duration_min` 1~80 / `resolution_hours` 0.2~97.1.
- **쓰면 안 되는 컬럼**
  - `is_recontact`: 고객별 첫 문의로 계산해 교차하면 첫 문의인데 true 5,339건, 첫 문의가 아닌데 false 7,303건. 정의 확인 전에는 재문의율에 쓰지 않는다.
  - `resolution_hours`: 진행중 2,002건·보류 1,015건에도 값이 모두 있다(평균 진행중 13.9 · 보류 14.1 · 완료 14.5, 최댓값은 진행중 97.1이 완료 89.0보다 큼).
  - `duration_min`: 채널별 평균이 13.2~13.3으로 사실상 같고 최솟값도 모두 1. 챗봇·이메일에도 응대 시간이 있는 셈이라 의미가 의심된다.
  - `ticket_category = 해지`: 4,260건 중 3,911건(약 92%)이 이탈하지 않은 고객(`is_churned=false`)이다. 해지 완료로 쓰면 안 된다.
- **데이터를 만든 사람에게 물을 것**
  1. `is_recontact` 정의(며칠 이내, 같은 고객/카테고리 기준?)와 첫 문의인데 true인 5,339건의 이유는?
  2. 진행중·보류 건의 `resolution_hours`는 예상 시간인가, 경과 시간인가?
  3. `duration_min`은 무엇의 시간인가? 챗봇·이메일에도 값이 있는 이유는?
  4. 해지 문의의 92%가 비이탈 고객인 이유는? 방어 성공, 철회, 오분류 중 무엇인가?
  5. 2025년 전체의 스냅샷인가? 진행중 2,002건·보류 1,015건은 추출 시점 상태인가?

## usage_monthly

- **그레인**: 고객 × 월. 523,825행 × 9컬럼.
- **키**: (`customer_id`, `year_month`) 유일. 고유 고객 49,985명, 12개월.
- **기간**: 2025-01 ~ 2025-12. 빠진 달 없음. 월별 43,845(1월) → 43,412(12월)로 완만히 감소(이탈 이후 행이 없음, 이탈 고객의 이탈 이후 행 0건, 가입 이전 행 0건).
- **결측**: 전 컬럼 null 0. `year_month`는 `YYYY-MM` 문자열(DATE 아님) → 날짜 비교는 `strptime` 변환 필요.
- **조인**: customers와 **N:1**. customers에 없는 `customer_id` 0개. customers에 LEFT JOIN 하면 **523,825행**(그대로). 반대로 customers 기준으로 붙이면 고객당 최대 12행으로 늘고, usage가 한 번도 없는 고객 **15명**은 usage 컬럼이 null인 1행이 된다.
- **값 범위**: `data_gb` 0.23~128.27 / `voice_min` 55~239 / `sms_count` 0~32 / `billing_amount` 10,450~100,480 / `app_login_count` 0~36 / `service_count` 0~12.
- **쓰면 안 되는 컬럼**
  - `is_active`: 523,825행 전부 True. 이탈 고객(7,241명)의 행 46,280개도 True → 정보가 없다.
  - `service_count`: 0인 행 47,425개(약 9.1%)가 전부 `is_active=True`, `billing_amount>0`. `billing_amount`와의 상관 0.002. 의미 확인 전까지 보류.
  - `billing_amount`: customers.`monthly_fee`보다 작은 행 465,995(89%) · 같은 행 12,848 · 큰 행 44,982. 플랜별 평균 청구액이 요금의 약 0.75~0.8배(예: 5G스탠다드 40,635 vs 55,000). 할인·부가세 여부를 확인하기 전에는 "요금"으로 쓰지 않는다.
  - `app_login_count = 0`인 131행도 모두 `is_active=True`.
- **데이터를 만든 사람에게 물을 것**
  1. `is_active` 정의는? 이탈 고객 행도 True인 이유는?
  2. `service_count`는 무엇을 센 값인가? 0인데 청구되는 47,425행은 정상인가?
  3. `billing_amount`는 `monthly_fee` 대비 어떤 기준으로 차감·추가되었나(할인·부가세·초과요금)?
  4. 이탈 고객의 마지막 행은 이탈월 직전월인가, 이탈월인가?
  5. usage가 없는 15명은 누구이며 왜 없나? 가입 직후 이탈인가?
  6. 행이 없는 달은 사용량 0인가, 계약 종료인가? (`voice_min` 최솟값이 55라 0인 행이 없다)

## 분석 전에 알아 둘 것

1. 세 테이블 모두 `customer_id`로 customers에 N:1이고 고아 키 0이라 LEFT JOIN은 행 수가 그대로다. 고객 기준으로 붙일 때만 행이 늘고 빠진다(문의 없는 고객 26,602명, usage 없는 고객 15명).
2. 이탈 정보는 2025년 이탈만 담겨 있어(2024년 이전 이탈 기록 없음) 전체 기간 이탈률·생존 분석은 편향될 수 있다.
3. `is_active`, `service_count`, `is_recontact`, `resolution_hours`, `duration_min`은 이름과 값이 맞지 않아 정의 확인 전에는 쓰지 않는다.
4. `visitor_id`·`campaign_id`는 2025년 가입자(6,485명)에게만 있고, 캠페인 기간과도 86%가 어긋난다.
5. 2024-12(가입 25건)와 2025-01~02 가입 저조는 실제인지 누락인지 모르니 가입 추이 해석에 주의한다.
